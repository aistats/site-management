## Summary

Add a **scripted sync pipeline** between [virtual.aistats.org](https://virtual.aistats.org/) and the yearly GitHub Pages site (`aistats20XX`). The year site remains **primary**: the tool compares converted virtual content to existing year-site pages, reports drift, and only writes when organisers explicitly choose to. It must not silently overwrite year-site prose that disagrees with virtual.

Conversion of virtual HTML uses **pandoc** plus deterministic post-processing and must preserve **source wording** when material *is* taken from virtual. Human paraphrase of virtual pages is out of scope and was the wrong approach for the 2026 backfill.

When the year site and virtual disagree, the default outputs are (1) a **reviewable diff** and (2) a **virtual update request** summary that chairs can send to the corporate operator of virtual. Optional `--apply-from-virtual` (or per-page accept) pulls virtual wording onto the year site only when chosen.

The inventory of *what* to sync is guided by the `stub` template. Early mapping work on `aistats2026` branch [`sync-from-virtual`](https://github.com/aistats/aistats2026/tree/sync-from-virtual) shows page destinations; this CIP replaces *how* sync is done. Decisions about what belongs on stub vs virtual are partially in CIP-0001 but may need to be modified.

**Which requirements does this CIP address?** None yet. Related work: CIP-0001 (stub page set and virtual-vs-Jekyll split), CIP-0003 (organiser timing for when pages land).

## Motivation

Year sites on GitHub Pages are the main reference of stable conference text. Virtual is a live schedule site. Some chairs are choosing to use virtual for other aspects of the conference. But it is important that the main site remains the long-term record of the conference.

The September 2026 `aistats2026` experiment showed the failure mode clearly: the page pointed towards virtual, and many pages that should be on the main site ended up residing there. A second failure mode is the inverse: blindly copying virtual onto `aistats20XX` would treat the year site as a disposable mirror and erase intentional primary-site content.

Organisers need a repeatable way to see where the two systems diverge, pull from virtual when that is correct, and otherwise produce a clear request for the virtual operator to update their side.
## Detailed Description

### Design principles

1. **Year site is primary.** `aistats20XX` is the long-term record. Sync never overwrites existing year-site pages by default. Missing pages may be proposed as new files; existing pages are compared and reported.
2. **Faithfulness when converting.** Convert virtual HTML; do not rewrite. Post-processing may strip chrome, inject front matter, rewrite absolute links, and normalise whitespace. It must not invent or summarise prose.
3. **Manifest-driven.** A YAML (or similar) map declares virtual URL → year-site path → extract rules. The stub page set (and early `sync-from-virtual` mapping) is the first concrete inventory; later years copy and edit the URLs.
4. **Deterministic compare.** Same HTML input → same candidate markdown (modulo declared options). Default mode is report/diff only.
5. **Two-way remediation.** Drift can be resolved by (a) explicitly applying virtual → year site, or (b) emitting a **virtual update request** that states what the year site has and what virtual currently shows, for the corporate operator of virtual.
6. **Respect the virtual/Jekyll split** (stub README / CIP-0001): do not dump interactive calendars, paper browsers, or booking engines into markdown. Those stay as links.

### Pipeline stages

```text
virtual URL(s)                    aistats20XX page(s)
    → fetch + optional fixture        → read existing markdown
    → extract main content
    → pandoc HTML → markdown
    → post-process (front matter, links, assets)
    → normalise both sides for compare
    → classify: missing | match | drift | year-only | virtual-only
    → default: write sync report + diffs + virtual-update-request.md
    → optional: apply selected pages from virtual onto year site
```

| Stage | Responsibility |
|-------|----------------|
| Fetch | Download HTML; record URL, timestamp, HTTP status; optional offline replay from fixtures |
| Extract | Remove nav/footer/cookie chrome; keep the article body. Selectors configurable per page class (Call, FAQ, Guidelines, Hotels, Invited bios, Awards) |
| Pandoc | HTML fragment → markdown. Prefer pandoc over ad-hoc regex for lists, headings, and links |
| Post-process | Prepend Jekyll front matter from the manifest; rewrite internal virtual links where a mapped page exists; download speaker/award images into `assets/images/` when requested; strip empty pandoc artefacts |
| Compare | Diff candidate body against existing year-site body (ignore front matter / generated date chrome as configured). Classify each mapped page |
| Report | Human-readable summary + unified diffs; plus a **virtual update request** document for pages where year-site content should win |
| Apply (opt-in) | Only with `--apply-from-virtual` and/or per-page accept list: write candidate markdown into the year repo |

### Sync outcomes (per page)

| Classification | Meaning | Default action |
|----------------|---------|----------------|
| **missing on year site** | Mapped page absent in `aistats20XX` | Propose new file in report; create only if `--apply-from-virtual` (or `--fill-missing`) |
| **match** | Bodies equivalent after normalisation | Note OK; no write |
| **drift** | Both exist; bodies differ | Show diff; **do not overwrite**. Offer apply-from-virtual *or* include in virtual update request |
| **year-only** | Page exists on year site; no virtual source in manifest | Report only (primary-site content) |
| **virtual-only / unmapped** | Content on virtual outside manifest | Optional inventory note; no auto-import unless added to manifest |

**Overwrite policy:** applying virtual onto the year site requires an explicit flag (global or `--only id1,id2`). There is no “sync means pull everything” default.

### Virtual update request

For each **drift** (and optionally year-only policy pages), generate a section suitable to send to the virtual operator, for example:

- Page identity (year-site path + virtual URL)
- Short statement: year site is authoritative for this content; please update virtual to match
- Year-site excerpt or link to the GitHub blob/PR
- Virtual excerpt or fetched snapshot timestamp
- Optional attached diff (year ← virtual) so they can see what to change

Output path sketch: `sync-report/YYYY-MM-DD/virtual-update-request.md` (and/or `.txt` for email). This is a **request artefact**, not an API push into virtual (virtual remains externally managed).
### Inventory that should primarily be on Main Site

These are the **destinations** the importer should know how to fill. Source URLs are the 2026 virtual paths; the year and path prefix are parameters.

| Year-site path | Virtual source (2026) | Notes |
|----------------|----------------------|--------|
| `call-for-papers.md` | `/Conferences/{year}/CallForPapers` | Full call body |
| `code-of-conduct.md` | `/Conferences/{year}/CodeOfConduct` | Full CoC |
| `faqs.md` | `/Conferences/{year}/SubmissionFAQ` | Preserve Q&A structure |
| `camera.md` | `/Conferences/{year}/CameraReadyInstructions` | |
| `poster.md` | `/FAQ/PostersInstructions` (or year-specific if moved) | |
| `reviewer_guidelines.md` | `/Conferences/{year}/ReviewerGuidelines` | Long; still convert faithfully |
| `ac_guidelines.md` | `/Conferences/{year}/ACGuidelines` | |
| `journal-track.md` | `/Conferences/{year}/CallForJournalTrack` | |
| `workshops.md` | `/Conferences/{year}/CallForWorkshops` | |
| `accommodation.md` | `/Conferences/{year}/Hotels` | |
| `visa.md` | `/Conferences/{year}/VisaTravelInformation` | |
| `invited.md` | `/virtual/{year}/eventlistwithbios/Invited%20Talk` | Bios + image fetch |
| `awards.md` | `/virtual/{year}/eventlistwithbios/Award` (+ home award blurb if needed) | Structure into award sections without changing citations |
| `registration.md` | Partial: Dates / home registration blurbs | Prefer extract of registration-related blocks + link to portal |
| `schedule.md` | Meeting dates from Dates + link to `/virtual/{year}/calendar` | Do not inline the full calendar |
| `dates.md` | Mostly generated from `_config.yml` via `listdates.html` | Importer may **update deadline YAML** from the Dates tables rather than owning prose |
| `_config.yml` (`conference.dates`, `deadlines`, venue fields) | `/Conferences/{year}/Dates`, Hotels | Structured extract → YAML merge (separate from pandoc prose path) |
| `index.md` | Home announcements (selective) | High risk of clobbering; default to **append/merge blocks** or skip unless `--include-index` |

**Out of scope for body import (link only):** interactive calendar, papers list, sponsor portal, registration checkout, OpenReview paper browser.

### Manifest sketch

```yaml
year: 2026
virtual_base: https://virtual.aistats.org
target_repo: ../aistats2026   # or explicit path
pages:
  - id: call-for-papers
    url: /Conferences/2026/CallForPapers
    out: call-for-papers.md
    extract: main_after_nav   # named strategy
    required: true            # must appear in sync report
    on_drift: report          # report | prefer_year | prefer_virtual (apply still needs CLI flag)
    front_matter:
      title: Call for Papers
      layout: default
      weight: 2
      hide: false
  - id: invited
    url: /virtual/2026/eventlistwithbios/Invited%20Talk
    out: invited.md
    extract: event_bios
    assets: speaker_images
    required: true
    on_drift: report
# ...
```

Default `on_drift: report` means classify + diff + virtual update request; never overwrite unless the operator passes `--apply-from-virtual`.

### Tooling home

| Option | Role |
|--------|------|
| **Preferred:** `site-management/scripts/sync_virtual/` (or similar) | Owns the sync tool; year repos remain content-only |
| Stub `_doc/` | Short “how to sync with virtual” pointing at the script |
| Year repo | Primary content; optional checked-in `virtual-sync.yml` override for that year |

Dependencies: Python 3 (fetch, BeautifulSoup or lxml extract, YAML, diff), system **pandoc**. Avoid committing converted blobs into `site-management`; fixtures for tests are fine.

### CLI sketch

```text
sync-virtual --manifest PATH --year 2026
    # default: fetch, convert, compare, write sync-report/ (diffs + virtual-update-request)

sync-virtual ... --fill-missing
    # create year-site pages that are absent but mapped (still no overwrite of existing)

sync-virtual ... --apply-from-virtual --only call-for-papers,camera
    # explicit overwrite of listed existing pages from converted virtual

sync-virtual ... --report-dir PATH
```

### Relationship to the rolled-back 2026 work

- `gh-pages` on `aistats2026` stays at the pre-backfill tip until sync quality is trusted.
- `sync-from-virtual` remains a **reference inventory and rough shape**, not a gold standard for prose.
- After the tool works, use report → selective apply (or virtual update requests) rather than bulk paraphrase PRs.

### Alternatives considered

| Approach | Why rejected |
|----------|----------------|
| Manual rewrite / LLM paraphrase | Wording drift; already failed for 2026 |
| Always overwrite year site from virtual | Treats `aistats20XX` as secondary; loses primary-site authority |
| iframe / permanent redirect only | Weak long-term record; breaks when virtual rotates years |
| Raw HTML drop into Jekyll without pandoc | Theme expects markdown + front matter; harder to review in git |
| Single giant “mirror site” crawl | Violates virtual/Jekyll split; huge noisy diffs |
| Automated write-back API to virtual | Virtual is corporate-managed; out of scope—emit a request document instead |

## Implementation Plan

1. **Manifest + inventory**
   - Encode the stub / `sync-from-virtual` path list as the default 2026 manifest.
   - Document extract strategies (`main_after_nav`, `event_bios`, `dates_tables`).

2. **Core CLI (compare-first)**
   - `sync-virtual --manifest PATH --year 2026` → report + diffs + virtual update request.
   - Fetch, extract, pandoc, post-process, compare; no overwrite by default.

3. **Opt-in apply paths**
   - `--fill-missing` and `--apply-from-virtual [--only …]` with clear logging of what will be written.

4. **Structured YAML path**
   - Parser for Dates / Hotels tables → proposed `_config.yml` deadline and venue patches (reviewable diff, not silent overwrite of chairs).

5. **Fixtures and tests**
   - Store HTML snapshots under `scripts/sync_virtual/fixtures/`.
   - Golden conversion snippets; tests that existing year-site files are unchanged unless apply flags are set.
   - Fixture pairs that exercise match / drift / missing classifications.

6. **2026 validation**
   - Run sync against live or fixture 2026 URLs on a clone of `aistats2026`.
   - Review report; selectively fill missing pages; use virtual update request where year-site (or intended primary text) should win.
   - Human review of any applied pages against virtual wording (not against the paraphrased branch).

7. **Stub / organiser docs**
   - Add `_doc/virtual-sync.md` (or checklist/timeline section): when to run sync, how to read the report, how to send the virtual update request (ties to CIP-0003 bands).

## Backward Compatibility

- No change to published year sites until organisers explicitly apply and merge.
- Stub page filenames stay as in CIP-0001; the sync tool targets that contract.
- Existing hand-written pages are never overwritten unless `--apply-from-virtual` selects them.

## Testing Strategy

- Unit tests on extractors with fixture HTML (2026 Call for Papers, CoC, Submission FAQ, Invited Talks).
- Pandoc availability check in CI or a clear skip message.
- Default-mode test: dirty year-site fixture must remain byte-identical after sync without apply flags.
- Drift fixture: report lists the page, emits a non-empty diff, and lists it in `virtual-update-request.md`.
- Apply-mode test: only `--only`-listed paths change.
- Manual acceptance: converted candidate matches virtual sentences (link/format normalisation only).
