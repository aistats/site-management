## Summary

Add an empirical **weeks-before-conference** organiser guide to the conference stub (`_doc/timeline.md`), synthesised from Valencia-era site git history (AISTATS 2023–2025) and `_config.yml` deadline fields. Cross-link it from `_doc/README.md` and the existing checklist; fix checklist path drift left over from the stub refresh.

**Audience**: organising chairs and anyone updating the year site. This is not a dedicated Area Chair review handbook; AC/review milestones appear only where they drive public deadlines and site pages.

**Which requirements does this CIP address?** None yet. CIP-0001 delivered the stub consumer; this CIP adds organiser timing guidance on top of that template.

## Motivation

New organising teams inherit a stub checklist that is ordered but **not week-relative**, and they learn site timing by copying last year’s panic. Commit history on `aistats2023`–`aistats2025` shows a repeatable pattern: the year repo appears ~37–41 weeks before the meeting, CFP and chairs land early, then **invited speakers and the programme schedule** often appear only in the final 1–6 weeks. Registration messaging and awards are similarly late relative to attendee need. Proceedings links often land **after** the conference.

Chairs need a playbook that:

1. States recommended T−Nw bands for organising actions and the stub files to update.
2. Contrasts **observed** (what recent years actually committed) with **recommended** (earlier publication where lag hurts authors and attendees).
3. Ties bands to the `_config.yml` deadline contract so key dates on `dates.md` stay the source of truth.

Without this, each year rediscovers the same late schedule/invited-speaker crunch that CIP-0001’s stub alone cannot prevent.

### Evidence summary (2023–2025)

Canonical conference starts used for week offsets:

| Year | Location | Start date |
|------|----------|------------|
| 2023 | Valencia | 2023-04-25 |
| 2024 | Valencia | 2024-05-02 |
| 2025 | Mai Khao | 2025-05-03 |

Repo creation clusters ~**37–41 weeks** before start (2023-08-03, 2023-07-14, 2024-07-29).

| Theme | Typical first site activity (weeks before start) | Often late relative to need |
|-------|--------------------------------------------------|----------------------------|
| CFP / deadlines in `_config.yml` | ~35–37w | Deadlines edited repeatedly through submission season |
| Committee / chairs on site | ~37–40w | Names still changing late (2024: session chairs ~1w) |
| Reviewer/AC guideline pages | ~34w (2025) or copied early from prior year (2023) | — |
| Registration links | ~14–17w (2023/25); 2024 earlier but thin | Early-reg messaging often near deadline |
| Invited speakers page | ~10w (2023), **~1–6w** (2024/25) | Consistently late for attendees |
| Schedule / programme | **~1–4w** | Heaviest commit burst in final month (2025 April) |
| Camera / paper pack | Mixed; 2025 early then again at 0w | Proceedings often **post**-conference |
| Awards | ~1–9w or post-conf | — |

`_config.yml` deadline lists (especially 2025’s richer chain) supply **process** anchors. Commits show **when the public site caught up** — often later than ideal. Method: author-date `git log` with keyword buckets, plus deadline YAML extraction. Raw notes live in [`cip/cip0003/evidence.md`](./cip0003/evidence.md).

### Target artefact: `_doc/timeline.md`

Organise as **T−Nw** bands. Each band lists organising actions, stub/site files to touch, and an observed-vs-recommended note where history shows lag.

| Band | Intent |
|------|--------|
| **T−40+** | Create year repo from stub; `baseurl` / `repository` / chairs stubs; banner; `draft: true` |
| **T−26–39** | Venue and meeting `dates:`; full deadline skeleton in `_config.yml`; CFP / CoC / FAQ pages; submission URL when OpenReview opens; seed reviewer/AC guidelines |
| **T−16–25** | Review season communications; keep deadline `important` / `old` flags honest on `dates.md`; registration provider selection |
| **T−12–15** | Decision notifications (or earlier if PC calendar demands); registration page live; early-bird deadline published |
| **T−8–11** | Invited speakers page (recommended **here**, not T−1–6); camera-ready instructions; visa/travel notes if local chairs have them |
| **T−4–7** | Programme draft on `schedule.md`; poster instructions; awards page if known; hide_tentative / draft flags |
| **T−1–3** | Final schedule; session chairs; last registration messaging; social/local pages if used |
| **Week of** | Day-of corrections; paper-pack / virtual-site links |
| **Post** | Proceedings URL (`proceedings.show`); Test-of-Time / awards cleanup; archive notes for society site |

Recommended vs observed (design targets for the guide prose):

- **Invited speakers**: recommend first public names by **T−8–11**; call out 2024/25 observation of T−1–6 as too late.
- **Schedule**: recommend draft by **T−4–7**, freeze by **T−1–3**; call out concentration of commits in the final fortnight.
- **Registration**: recommend page + early deadline by **T−12–15**, not only when early-bird is about to close.

### Checklist integration

[`stub/_doc/checklist.md`](https://github.com/aistats/stub/blob/gh-pages/_doc/checklist.md) stays the **unordered work inventory**; `timeline.md` owns **when**. After Accept:

1. Link checklist items to timeline bands (and vice versa).
2. Fix obsolete paths (`speakers.html` → `invited.md`, `sponsors.html` if removed, etc.) so checklist matches CIP-0001 page set.
3. Point `_doc/README.md` at both checklist and timeline as first reading for new GCs/PCs.

### Out of scope

- Rewriting OpenReview / CMT process itself
- Theme or Fenner work ([CIP-0002](./cip0002.md))
- Back-porting the guide into already-running yearly repos (optional follow-up)
- A full Area Chair meta-review handbook (seeded `ac_guidelines.md` already covers process text)

### Alternatives considered

1. **Public site page** (`timeline.md` in the nav) — useful for transparency, but week-relative advice is for chairs; keep under `_doc/` first; promote later if wanted.
2. **Encode timing only in checklist numbering** — fails to express calendar pressure or observed lag.
3. **Hard-code absolute calendar dates** — breaks across years; weeks-before-start scales with May (or April) meetings.
