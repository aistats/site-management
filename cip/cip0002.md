## Summary

One programme to modernise [`aistats/jekyll-theme`](https://github.com/aistats/jekyll-theme): tidy the Minima-era theme and confirm Jekyll/Pages compatibility; install the shared CiteProc publication stack from [`lawrennd/jekyll-fenner`](https://github.com/lawrennd/jekyll-fenner); clarify or retire the opaque `style: aistats` branding switch; then refresh cite presentation styling.

Phases are tracked as **backlog tasks** under this CIP (not separate CIPs).

## Motivation

`aistats/jekyll-theme` is a Minima-derived multi-brand theme. Conference stubs and the society site depend on it via `remote_theme`. Its publication/cite machinery is Fenner’s **legacy path-2** encoding (`paper_abstract` under `layout: default`), duplicated across forks while Fenner already maintains the shared core and an idempotent install.

The gemspec still presents as upstream Minima. Branding via `site.style` is effective but opaque to organisers. Cite UI presentation is dated once the stack is Fenner-backed. Doing hygiene, Fenner install, branding, and cite styling as four CIPs over-fragments one theme programme; one CIP with ordered backlog tasks matches how the work will actually ship.

CIP-0001 refreshed the stub; this CIP refreshes the **theme** those stubs consume.

## Detailed Description

### Work repos

- Primary: **`aistats/jekyll-theme`**
- Consumed: **`~/lawrennd/jekyll-fenner`** (install only; do not reimplement Fenner)
- Follow-up: stub `_config.yml` / README when branding or Fenner wiring requires consumer changes

### Phase A — Theme tidy and Jekyll compatibility

- Inventory AISTATS-needed vs unused Minima samples (`_posts`, stock `about.md`, screenshots, unused skins).
- Align gemspec/Gemfile identity with `aistats/jekyll-theme` without breaking `remote_theme` consumers.
- Confirm builds against current GitHub Pages Jekyll; fix blocking deprecations; document supported range.
- Keep chrome local: headers, footers, `_includes/aistats/`, AISTATS (and other) Sass/CSS skins.

### Phase B — Integrate jekyll-fenner for CiteProc rendering

1. Install from Fenner (`FENNER_ROOT=~/lawrennd/jekyll-fenner`, copy mode for Pages) using Fenner’s ownership manifest.
2. Preserve AISTATS chrome; replace only Fenner-owned publication/cite/SEO paths.
3. Keep a **path-2 adapter** where needed (thin `paper_abstract` → shared body), unless a low-risk path-1 migration is clearly better.
4. Keep `assets/bib/citeproc.yaml` (and related exports) coherent with the installed field model.
5. Smoke-build theme + at least one consumer (stub and/or a year site that exercises cite UI).

### Phase C — Branding (`style: aistats`)

Redesign how the theme selects brand chrome so stubs need a clearer contract than a magic `style: aistats` key (default AISTATS when unset, rename to `brand:`, or split themes). Until this phase lands, stubs keep `style: aistats`. Do this after Fenner install so branding work does not collide with cite-stack file ownership.

### Phase D — Cite presentation styling

Refresh visual/UX of cite affordances (Cite this paper, copy buttons, export panels) in theme CSS and, where shared, Fenner templates. Field model and export contents stay equivalent unless a Fenner CIP expands behaviour. Prefer completing Phase C first so cite chrome matches the new branding contract.

## Implementation Plan

Ordered backlog (see Implementation Status):

1. Branch on `aistats/jekyll-theme` (`cip0002-theme-modernise` or similar).
2. Phase A tidy + Jekyll/Pages pass.
3. Phase B Fenner install + adapter + smoke.
4. Phase C branding contract + stub config/docs update.
5. Phase D cite styling + smoke.
6. Release notes for chairs / `remote_theme` consumers.

## Backward Compatibility

- Existing `remote_theme: aistats/jekyll-theme` sites should keep building across phases.
- Prefer additive Fenner install; document any required `_config.yml` bumps.
- Do not remove `style: aistats` until Phase C ships a migration path.

## Testing Strategy

- `bundle exec jekyll build` on theme and Pages-compatible config each phase.
- Consumer builds (stub / recent year) after Fenner and after branding.
- Spot-check cite-as UI, BibTeX/APA/RIS/EndNote, `citeproc.yaml`, Scholar/OG/Twitter metas after Phases B and D.
- Optional Fenner path-2 fixture smoke against the installed theme.
